# Generic diagrams

Issue #99 introduces a read-only General View on the accepted development baseline, including PR #76 and PR #111. In an editor group's add-tab menu, **General View** opens the selected canonical element and its direct members (or the first available Browser root). **General View example** opens an explicit in-memory heterogeneous SDK model. Neither action saves model or layout data to Fabric.

## Boundaries and reuse

- Model/Diagram records describe notation and occurrences. Occurrence GUIDs distinguish graphical instances from semantic element IDs. Canonical object references also distinguish models with overlapping IDs.
- ViewModel/Diagram projects an explicit model slice and owns each tab's session viewport. Selection uses the existing circuit-scoped IElementSelectionService. Self-generated selected-element URL round trips preserve the selected canonical object; initial and external navigation still use the accepted resolver. Composition applies one-use history-entry state with a service-issued request; a matching external URI or a cancelled request alone never authorizes the shortcut. The projector never writes to canonical objects.
- Components/UI/Organisms/Diagram contains the single Z.Blazor.Diagrams adapter and reusable node shell, name compartment, text/graphical compartment, four-sided boundary feature, edge, package/comment nodes and General View root. Shell slots order name, nested view, compartments, then boundary features. Feature membership is rendered with diamonds rather than nested boxes; namespace membership has different notation and is explicitly omitted.
- Edge records carry separate endpoint markers, role/multiplicity/adornment labels, optional middle text, boundary endpoints and polyline bends. Compartment title/member selection is caller data; the component does not duplicate the 66 compartment productions.
- DiagramNamePresentation takes aliases explicitly. The default projector obtains local alias memberships. Declarations and values are emitted by SysML2.NET's BuildDefinitionDeclaration, BuildUsageDeclaration and BuildValuePart. A declaration-only SDK cursor handles unordered API body relationships without mutating the model.

The default slice takes at most 200 requested elements and exposes omitted or unavailable content with an ellipsis. Binary edges require exactly one canonical source and target; n-ary relationships are not approximated. Namespace owned-membership has distinct BNF notation that is not implemented here; it raises the omission indicator even when both member nodes are visible. A valid binary connector is accounted for by its usage edge, without a false node-absence warning. Membership already represented by a boundary feature is not duplicated as a self-loop. Inline attribute membership does not require a duplicate edge. Unrepresented owned namespace members and unavailable annotation targets raise the omission indicator; root membership enumeration stays lazy until the slice limit is applied.

Mounted renderers borrow tab state. Native gestures update the ViewModel viewport immediately; unmount unregisters all installed behaviors without a late state write; tab close disposes its ViewModel. The canvas host waits for pending initialization before disposing the SDK observer/reference. Initial fit-to-view accounts for boundary labels; the accepted ZoomControls component supplies keyboard-accessible zoom navigation. Nested views use the same renderer and tab-owned child state. Node rectangles remain fixed by presentation geometry. A keyboard-focusable scroll region contains long declarations, rows and nested views; it never expands the native anchor rectangle. Boundary labels are limited to 200 model pixels and expose the full text through their accessible label and title. Fit and native/control zoom share a 0.1% minimum, allowing the maximum 200-node default slice to fit a normal canvas. Nested canvases own their pointer events independently of the parent selection surface. No model create/delete, node resize, Browser-to-canvas drag/drop, toolbox or port-moving behavior is enabled. Existing editor-tab drag/drop and workspace resizing remain available.

## Functional project context (PR #111)

The accepted `AddOrganizationServices` registration supplies one scoped `IMockedDataService` functional-data graph per circuit. `MockedDataService` creates Mycelium.SDK 0.2.0 organizations, projects, users, ownerships, policies and reviews with cross-references. These functional-data objects are not SysML2.NET `IElement` instances. The accepted placeholder services consume that graph; feature code should use `IOrganizationContextService` for account/organization context and `IOrganizationProjectService.GetProjectsAsync` for functional projects. Existing organization context/header ViewModels share circuit scope, while the projects-page factory creates page-owned state. These contracts remain the boundary for a later Fabric implementation; diagram components should not inject the concrete mock service or copy its datasets.

The current #99 workspace route has no selected functional project or project-to-model association. General View projects the selected canonical SysML element from shared selection, or the first available Browser root. The separate General View example creates an explicit session-only SysML graph to exercise the seven graphical building blocks. It supplies no organizations, functional projects, accounts or reviews, so it does not duplicate PR #111's application data. The functional mock service supplies no equivalent SysML graph and cannot replace that example.

SysML loading remains behind the accepted `IModelLoaderService`: JSON DTOs are synchronized through the scoped SysML2.NET assembler, which owns canonical loaded-element identity. `IElementIdResolver` resolves stable SysML ElementIds from that assembler cache, ensuring the default Quantities library is loaded. `IElementSelectionService` remains the shared canonical selection authority; diagram projection and tab-owned ReactiveUI presentation receive SDK elements without owning functional data or loading another model.

`FunctionalProject.EngineeringProjectId` and the mock engineering metadata, branch and review-target IDs do not supply a SysML payload, model URI or established model-session mapping. They must not be equated to a namespace/element identity or used to associate a functional project with Quantities or GeneralViewExample automatically. The accepted project placeholder also returns all mocked projects of an organization; its future visibility rule must not be represented as implemented authorization.

Future project-aware workspace navigation should obtain organization context and projects through the accepted organization service contracts in the composition layer. A project/branch-to-model association and a corresponding model-loading/session contract are prerequisites before opening that project's canonical SysML elements. Project-specific access, ownership metadata and review links likewise need real engineering associations. Those workflows belong to follow-up work; the reusable renderer remains independent of both the functional-data provider and Fabric transport. No additional runtime integration or synthetic integration test is introduced for an association that does not exist.

## Reactive ownership

| Component | Base and state | Observation and ownership |
| --- | --- | --- |
| GeneralDiagram | BloomReactiveComponentBase&lt;IGeneralDiagramViewModel&gt; | Borrows the tab's projection and viewport; owns only its native renderer mount. |
| DiagramNodeWidget | BloomReactiveComponentBase&lt;DiagramNodeViewModel&gt; | Borrows one occurrence's notation, boundary presentations and selection decoration from the tab. |
| DiagramBoundaryFeature | BloomReactiveComponentBase&lt;DiagramBoundaryViewModel&gt; | Borrows one boundary occurrence's placement, label and selection decoration; captures selection and calls its VM action. |
| DiagramEdge | BloomReactiveComponentBase&lt;DiagramEdgeViewModel&gt; | Borrows relationship notation and selection; the library adapter still owns path geometry. |
| DiagramNodeShell | BloomComponentBase | Stateless ordered layout slots and a shape parameter. |
| DiagramNameCompartment | BloomComponentBase | Stateless immutable name presentation. |
| DiagramCompartment | BloomComponentBase | Stateless immutable rows/title and an optional graphical fragment. |
| DiagramPackageNode | BloomComponentBase | Stateless name and body fragment inside the occurrence's reactive boundary. |
| DiagramCommentNode | BloomComponentBase | Stateless text inside the occurrence's reactive boundary. |
| DiagramCanvasHost | Z.Blazor.Diagrams DiagramCanvas | Required third-party inheritance; preserves native JS initialization and asynchronous cleanup. The surrounding GeneralDiagram provides reactive binding. |

Pure structural fragments intentionally have no synthetic ViewModel or independent selection subscription. Their immutable inputs are supplied again when the owning occurrence presentation changes. All Bloom components expose the shared Class and AdditionalAttributes integration. The reactive bases detach component observation on unmount without disposing caller-owned presentation.

GeneralDiagram uses Blazor's RendererInfo.IsInteractive to mount the native canvas only in an interactive renderer. Static prerender emits the view frame without creating JS-dependent resources. No post-render StateHasChanged workaround is needed; bUnit integration fixtures explicitly select the Server renderer, while an HtmlRenderer regression verifies static rendering and disposal issue no JS calls.

GeneralDiagramViewModel has one `WhenAnyValue` subscription to the canonical selection service per retained view. Its reference-keyed index updates only the previously selected and newly selected node, boundary and edge occurrences. `IsSelected` is derived presentation decoration, never a second canonical selection service. Repeated occurrences have separate decorations; equal ElementIds from different canonical objects remain independent. The diagram root and renderer do not receive selection notifications, and the renderer does not refresh every native model for selection. Nested views have their own retained state and single service subscription, released when their parent association is removed or the tab closes.

Projection, viewport, occurrence notation and selection decoration use `RaiseAndSetIfChanged`. Synchronous selection and zoom actions need neither ReactiveCommand nor CanExecute plumbing. There is no asynchronous application action in this slice requiring command execution state, and no live model change stream requiring DynamicData. No Subject, OAPH, additional event bus or manual StateHasChanged call is used by these diagram components.

`UpdateProjection` accepts a validated immutable presentation replacement from composition on the owning circuit. It retains node/edge ViewModels by graphical identity and exact canonical reference, updates boundary presentations, and preserves the parent viewport. It rejects invalid endpoints before changing live state. A removed or replaced nested projection releases its old child state; an unchanged association retains it. The native adapter rebuilds the bounded graph in one library batch for an explicit projection replacement. This is a presentation contract for future integrations, not an editing, resizing or persistence UI. Ordinary selection does not rebuild the graph. Native resources and application presentation have separate owners throughout remounts and movement between editor groups.

Behavioral tests cover targeted renders across 200 nodes, actual ReactiveUI subscription ownership, repeated canonical occurrences, same-ID objects from different models, boundary and edge actions, projection replacement, native geometry, invalid snapshots, nested removal, VM replacement, remounts and tab close. The canvas inheritance exception is tested alongside disposal during pending native initialization. Browser scenarios verify real nested pointer behavior and published light/dark rendering separately from component tests.

## Relationship to PR #91

Selectively adapted concepts: the Z adapter, canonical/projection/presentation separation, occurrence identity, retained tab viewport, and the initialization-before-disposal canvas guard. No merge or cherry-pick was used.

The graphical BNF uses hollow triangles for subclassification/subsetting, a two-dot triangle for typing, and a barred triangle for redefinition. Markers extend away from the node rather than underneath its fill. Marker DOM IDs are unique per mount, even when presentations are reused across views.

Shared notation corrects the review's typed visible port labels, equals sign for attribute values, italic compartment headings, SDK connection declarations, plain edge labels, binding equals sign, and shell ordering. Interface connections have their own keyword. Flows are explicitly omitted with an ellipsis until a specialized projection supplies their payload and direction, so they are never misrepresented as plain connections.

PR #91 retains Interconnection-specific topology projection, nested part compartments, regional large-model navigation, model-opening/upload flows and its presentation serializer. On rebase it should produce shared node/edge presentations and consume this renderer rather than retain a second PartSvg/ConnectionSvg rendering stack.

Issues #100–#107 and #98 remain separate: resizing, Browser drag/drop, toolbox and creation actions, and boundary repositioning can update occurrence geometry, edge bends and boundary placements without changing semantic identities or replacing shared components. Persistence, live notifications, collaboration, backend permissions and full specialized-view notation are not implemented here.
